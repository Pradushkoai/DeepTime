# T-001: Архитектура движка — Спецификация

> 📋 **Спецификация T-001** — фундамент технической архитектуры: слои, ECS/DOTS, модули, game loop. На основе GDD §19 (технологический стек) + D-015 (контракт сессии).
>
> **Принцип**: отделение логики от рендера + детерминизм + ECS для 30 000+ агентов.

---

## 🎯 Обзор

Архитектура DeepTime — **четыре слоя**, каждый со своей ответственностью:

```
┌─────────────────────────────────────────────┐
│ 4. UI Layer (UI Toolkit)                    │  ← что игрок видит/нажимает
├─────────────────────────────────────────────┤
│ 3. Render Layer (Unity渲染)                 │  ← камера, модели, эффекты
├─────────────────────────────────────────────┤
│ 2. Simulation Layer (ECS/DOTS, детерминированная) │  ← чистая логика
├─────────────────────────────────────────────┤
│ 1. Data Layer (гекс-сетка, каталоги, сейвы) │  ← постоянные данные
└─────────────────────────────────────────────┘
```

**Главный принцип**: **симуляция (слой 2) не знает о рендере (слой 3) и UI (слой 4)**. Рендер и UI читают состояние симуляции, но не наоборот. Это даёт:
- Детерминизм (одинаковый seed + input = одинаковое состояние)
- Тестируемость (симуляция без рендера — быстро, headless)
- Мультиплеер (Q-018 — синхронизируется только input)
- Save/load (сохраняем только input, не всё состояние)

## 🏗 Слой 1: Data Layer (постоянные данные)

> То, что не меняется в рантайме. Загружается один раз при старте игры.

### 1.1 Каталоги (статические данные)

Источники: `docs/ai/02_world/resources/`, `processed_materials/`, `06_technology/items/`, `tech_tree.md`, `processes.md`.

**Формат**: ScriptableObject (Unity) или JSON + десериализация в immutable структуры.

| Каталог | Объём | Формат |
|---|---|---|
| Ресурсы (~349) | ~50 КБ JSON | `ResourceCatalog` |
| Материалы (~129) | ~30 КБ JSON | `MaterialCatalog` |
| Изделия (~113) | ~40 КБ JSON | `ItemCatalog` |
| Технологии (84) | ~20 КБ JSON | `TechTree` |
| Процессы (25) | ~5 КБ JSON | `ProcessCatalog` |
| Почвы (32 WRB) | ~10 КБ JSON | `SoilCatalog` |
| Флора (~150-200) | ~30 КБ JSON | `FloraCatalog` |
| Фауна (~140) | ~30 КБ JSON | `FaunaCatalog` |

**Игровые поля** (P5 из аудита Модели B — обязательны с v0.32):
- Каждый элемент каталога имеет 2-3 числовых поля (питательность/урожайность/трудоёмкость/урон и т.д.)
- Значения — на плейтестах, СУЩЕСТВОВАНИЕ полей — обязательно сейчас

### 1.2 Гекс-сетка мира (генерируется один раз)

Источник: GDD §4. Сетка 360×180 = 64 800 гексов. Каждый гекс — 50-100 км.

**Генерация** (offline, при сборке игры):
```
SRTM (рельеф) + OSM (реки/леса) + SoilGrids (почвы) + USGS (руды) + MODIS (растительность)
                          ↓
              Генератор гекс-сетки
                          ↓
              Бинарный файл (~200-500 МБ)
                          ↓
              Грузится в рантайме за ~2-5 сек
```

**Структура гекса** (GDD §4, 12 полей → расширено для D-013):
- `Coord` (lat/lon)
- `TerrainType`, `Biome`, `Elevation`, `Climate`, `Fertility`, `WaterAccess`
- `Resources` (surface/subsurface/deep)
- `Fauna`, `Flora` (ссылки на каталог)
- `Soil` (ссылка на почвенный каталог)
- `Region` (владелец-политик, меняется в рантайме)
- `Settlement` (ссылка на поселение, меняется)
- `VisibilityState` (D-013: unknown/observed/in-memory/known, меняется)
- `LastObservedTurn` (для устаревания в памяти)

Подробности — в T-004 (Гекс-сетка).

### 1.3 Стартовые конфигурации

- Архетипы (8 типов — GDD §8)
- Стартовые пакеты (D-008)
- Параметры сложности (на плейтестах)

### 1.4 Save Files

- SQLite (GDD §19) или BSON

## 🧠 Слой 2: Simulation Layer (детерминированная ECS)

> **Сердце игры**. Чистая логика, без рендера. Полностью детерминирована от seed + input.

### 2.1 ECS (Entity Component System)

Источник: GDD §19 (DOTS/ECS). Принцип:

| Концепция | Что | Пример |
|---|---|---|
| **Entity** | ID (без данных) | `citizen_12345` |
| **Component** | Данные (POD struct) | `Health { value: 75 }`, `Skills { hunt: 80, smith: 30 }` |
| **System** | Логика (обрабатывает компоненты) | `HealthSystem` обновляет `Health` каждый тик |

**Принципы ECS**:
- Компоненты — POD (Plain Old Data), в contiguous массивах (кеш-локальность)
- Системы — pure functions от компонентов
- Запросы (queries) — «дай все entity с Health AND Skills»
- Параллелизм — системы можно группировать и запускать в нескольких потоках

### 2.2 Главные сущности (entity archetypes)

Подробно в T-002. Кратко:

| Archetype | Компоненты | Кол-во в игре |
|---|---|---|
| **Citizen** | Identity, Age, Health, Skills, Needs, Family, Loyalty, Religion, Wallet, Position | 30 000+ |
| **Family** | Members, Property, Inheritance | ~5 000-10 000 |
| **Settlement** | Population, Buildings, Stockpile, Visibility | ~50-500 |
| **Building** | Type, Position, Workers, Stockpile | ~10 000+ |
| **Faction** | Type, Power, Grievance, Agenda | 3-9 |
| **Chief** | Identity, Era, Pressure, Legitimacy, Heir, Adaptations | 1 |
| **Army** | Units, Supply, Morale, Commander, Position | 0-10 |
| **Caravan** | Goods, Origin, Destination, Position | 0-50 |
| **AICiv** | Population, Resources, Techs, Factions, Wealth, Army, Relation | ~10-50 |
| **Event** | Type, Payload, Choices, Resolution | активные 5-20 |
| **Hex** | Coord, Terrain, Resources, Visibility, Region, Settlement | 64 800 |

### 2.4 Game Loop (главный цикл)

Связь с D-015 Контракт сессии:

```
GAME LOOP:
  while (game_running):
    1. READ INPUT (ход игрока: эдикты, приоритеты, реформы, выборы в событиях)
    2. SIMULATE TURN:
       2.1. EventSystem — сгенерировать события (D-016), предложить игроку выборы
       2.2. WAIT FOR PLAYER CHOICES (пауза симуляции, пока игрок решает)
       2.3. APPLY CHOICES (выборы игрока → изменения в ECS)
       2.4. RUN ALL SYSTEMS (по частотам тика — см. T-003)
       2.5. UPDATE CHRONICLE (D-001 — запись в хронику)
    3. CHECK END CONDITIONS (смерть вождя, вырождение, победа)
    4. UPDATE VISIBILITY (D-007, D-013)
    5. RENDER (слой 3) — асинхронно, не блокирует симуляцию
    6. UPDATE UI (слой 4) — асинхронно
```

**Важные принципы**:
- **Ход = атомарная единица** (1 год / 1 сезон / 1-5 лет — по темпу D-015)
- **Пауза для выбора** — симуляция ждёт, пока игрок выбирает в событии (D-016)
- **Автопрокрутка рутины** — в темпе «эпохи» (D-015) рутина автопрокручивается, игрок вмешивается по триггерам

### 2.5 Детерминизм

- **Seed** — число (int64), задаёт всю случайность
- **RNG** — детерминированный (PCG или xorshift), инициализируется seed'ом
- **Input log** — все действия игрока (эдикты, реформы, выборы в событиях)
- **Replay** — playback input log'а на том же seed'е = тот же результат

**Что НЕ детерминировано**:
- Рендер (FPS, камера, визуальные эффекты)
- UI (позиции окон, скролл)
- Эти слои не влияют на симуляцию

### 2.6 Псевдо-случайность (для UX)

> «Игрок видит 30% шанс успеха реформы, но провалил 3 раза подряд — фрустрация»

Решение: **Pseudo-Random Distribution (PRD)** — как в Dota 2. Шанс растёт после каждой неудачи, гарантируя, что 30% не означает «0 из 10».

## 🎨 Слой 3: Render Layer (Unity渲染)

> Визуализация состояния симуляции. Недетерминированный (зависит от FPS, камеры).

### 3.1 Три уровня рендеринга (GDD §19)

| Уровень | Когда | Что рендерится |
|---|---|---|
| **Близкий** (локальный вид) | Камера зумит в гекс | Ближние 100 граждан: 3D low-poly + анимация. Ближние 50 зданий: 3D детализированные. GPU instancing растительности. Полный post-processing. |
| **Стратегический** (высоко) | Камера высоко | Все граждане как 2D иконки/точки. Здания simplified 3D. Без пост-процессинга. Туман войны, торговые пути. |
| **Глобальная карта** | Камера на весь мир | 2D тайлы поверх реальной карты/глобуса. Иконки поселений, армий, караванов. UI-наложение. |

### 3.2 LOD (Level of Detail) — три версии моделей

- High poly (близко) — 5 000-10 000 треугольников
- Med poly (средне) — 500-1 000 треугольников
- Low poly (далеко) — 50-100 треугольников
- Impostor (очень далеко) — 2D биллборд

Движок выбирает автоматически по расстоянию до камеры.

### 3.3 GPU Instancing

- Растительность (трава, деревья, камни) — тысячи объектов в одном draw call
- Здания одного типа — batched
- Граждане на стратегическом уровне — points/instanced

### 3.4 Occlusion Culling + HLOD

- Occlusion culling — не рисуется то, что за горой/зданием
- HLOD — целые кварталы объединяются в одну модель на большом расстоянии

### 3.5 Анимация граждан

- Skeletal animation для 100 ближних граждан
- Для остальных — простые точки/иконки
- Анимации: ходьба, работа, бой, смерть
- Blend trees для плавных переходов

### 3.6 Видимые сущности (D-013, Д4)

> Караваны, армии, мигранты, экспедиции — движущиеся точки на дорогах.

- На дорогах (D-002) в зоне видимости (D-013)
- Иконка по типу (караван/армия/мигранты/экспедиция)
- Цвет по принадлежности (свой/сосед/враг)
- Анимация перемещения между гексами

## 🖥 Слой 4: UI Layer (UI Toolkit)

> Что игрок видит и нажимает. Читает состояние симуляции, отправляет input.

### 4.1 Главные экраны (D-007 + D-015)

| Экран | Что показывает | Спека |
|---|---|---|
| **Экран проблем** (D-007 инверсия) | Активные давления, подписи причин | D-007, R7 explainability |
| **Хроника дня** (R6) | Лента позитивных событий | D-007, D-016 |
| **Панель вождя** | Возраст/эра, давление, наследник, хроника | D-001 |
| **Диалог события** (D-016) | Портрет + текст + 2-4 выбора | D-016 |
| **Инспектор гражданина** (R7) | Текущее действие + причина + альтернатива | D-007, R7 |
| **Панель фракций** | Сила + обида по фракциям | D-004 |
| **Экран технологий** | Дерево техов, прогресс | research_system |
| **Глобальная карта** | Политическая, ресурсы, торговля | D-005, D-013 |

### 4.2 Принципы UI (из D-007)

- **Инверсия** — пусто = хорошо, показываем только активные давления
- **Подпись причины** — каждый алерт объясняет «почему»
- **Цвет = второй канал** — дополняет подпись, не заменяет
- **Отключаемые алерты** — для опытных игроков
- **Explainability** (R7) — причина каждого решения

### 4.3 UI Toolkit (Unity)

- Десктоп: UI Toolkit (современный, CSS-подобный)
- Android: UGUI или UI Toolkit (на плейтестах)
- Адаптивный layout (different resolutions)

## 🔌 Связь между слоями

### Data flow (как данные движутся)

```
1. Каталоги (Data Layer)
        ↓ (read-only)
2. Симуляция (Simulation Layer, ECS)
        ↓ (read state)
3. Рендер (Render Layer) → экран
        ↓ (read state)
4. UI (UI Layer) → экран
        ↓ (player input)
5. Симуляция (получает input на следующем ходу)
```

### Event bus (для UI updates)

UI не опрашивает симуляцию каждый кадр (дорого). Вместо этого:
- Симуляция публикует события (Event Bus)
- UI подписывается на нужные события
- Пример: `EventBus.Publish(new FactionGrievanceChanged(factionId, 45))` → UI обновляет панель фракций

### Command pattern (для input)

UI не меняет симуляцию напрямую. Только через команды:
- `CommandBus.Send(new SetResearchPriorityCommand(techId, priority))`
- Симуляция выполняет команду на следующем ходу
- Это даёт: undo/redo, replay, мультиплеер (синхронизация команд)

## 🧩 Модули (проектная структура кода)

### Структура проекта (Unity Assembly Definitions)

```
DeepTime/
├── Assets/
│   ├── _Data/                    # ScriptableObjects (каталоги)
│   │   ├── Resources/
│   │   ├── Materials/
│   │   ├── Items/
│   │   ├── Tech/
│   │   └── HexGrid/              # бинарный файл мира
│   ├── Plugins/                  # сторонние библиотеки
│   ├── Scripts/
│   │   ├── DeepTime.Simulation/  # asmdef: ECS, системы (детерминированная)
│   │   │   ├── Components/       # ECS-компоненты
│   │   │   ├── Systems/          # ECS-системы
│   │   │   ├── Catalogs/         # обёртки над ScriptableObjects
│   │   │   ├── Commands/         # CommandBus
│   │   │   ├── Events/           # EventBus
│   │   │   └── SaveLoad/         # сериализация
│   │   ├── DeepTime.Rendering/   # asmdef: рендер (недетерминированная)
│   │   │   ├── Camera/
│   │   │   ├── Meshes/
│   │   │   ├── LOD/
│   │   │   └── FogOfWar/
│   │   ├── DeepTime.UI/          # asmdef: UI Toolkit
│   │   │   ├── Screens/
│   │   │   ├── Widgets/
│   │   │   └── Input/
│   │   ├── DeepTime.Data/        # asmdef: Data Layer
│   │   │   ├── Catalogs/
│   │   │   ├── HexGrid/
│   │   │   └── SaveFiles/
│   │   └── DeepTime.Core/        # asmdef: общие интерфейсы, утилиты
│   │       ├── Events/
│   │       ├── Commands/
│   │       └── Math/
│   └── Scenes/
│       ├── MainMenu.unity
│       ├── Game.unity
│       └── Editor.unity          # для разработки/тестов
```

### Зависимости модулей

```
DeepTime.UI → DeepTime.Core (Events, Commands)
DeepTime.Rendering → DeepTime.Core
DeepTime.UI → DeepTime.Simulation (read state, send commands)
DeepTime.Rendering → DeepTime.Simulation (read state)
DeepTime.Simulation → DeepTime.Data (read catalogs)
DeepTime.Simulation → DeepTime.Core
DeepTime.Data → DeepTime.Core
```

**Принцип**: нижние слои не знают о верхних. Simulation не знает о Rendering/UI.

## ⚙️ Технологический стек (GDD §19)

| Компонент | Технология | Альтернатива |
|---|---|---|
| Движок | Unity 2022 LTS + C# | Godot 4 (open source, C#) |
| ECS | Unity DOTS | собственная ECS на C# |
| UI (десктоп) | UI Toolkit | UGUI |
| UI (Android) | UGUI | UI Toolkit |
| Геоданные (offline) | GDAL + QGIS | Python + rasterio |
| Гекс-система | H3 (Uber) | собственная (offset coords) |
| Сейвы | SQLite | BSON / MessagePack |
| Профайлинг | Unity Profiler + custom metrics | dotTrace |

**Решение по движку**: Unity 2022 LTS (GDD §19). Альтернатива — Godot 4 (open source, без лицензионных отчислений). Решение — на технической спеке T-007 (Производительность) после бенчмарка.
