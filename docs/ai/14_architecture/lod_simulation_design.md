# T-003: LOD-симуляция — Спецификация

> 📋 **Спецификация T-003** — 8 частот тика из GDD §7 + связь с D-015 (временной LOD игрока). Как 30 000+ агентов симулируются без тормозов.
>
> **Принцип**: ближайшие к камере граждане тикают каждый кадр, глобальные потоки — раз в несколько минут.

---

## 🎯 Обзор

GDD §7 даёт 8 уровней симуляции с разной частотой тика. Это позволяет балансировать глубину симуляции с производительностью: 30 000 граждан × 1 тик/сек = 30 000 ops/сек — слишком много. Но если ближние 100 граждан тикают 1/сек, а дальние агрегируются до 1/мин — подъёмно.

D-015 Контракт сессии добавляет **временной LOD игрока** (3 темпа: вождя/поколения/эпохи). Это другой уровень — игрок сам переключает темп, а не движок по расстоянию.

**Эта спека описывает**:
1. 8 частот тика из GDD §7 (движок)
2. Связь с D-015 (3 темпа игрока)
3. Бесшовный переход «личность → абстракция» (аудит Модели B, SoS сравнение)
4. Как агрегация работает для дальних граждан
5. Профиль нагрузки

## ⏱️ 8 частот тика (GDD §7)

| Частота | Что симулируем | Содержание | Системы |
|---|---|---|---|
| **1 тик/сек** | Отдельные граждане (ближние 30-100) | Действия, движения, эмоции | CitizenNeedSystem, CitizenActionSystem, CitizenMovementSystem, VisibilitySystem |
| **1 тик/10 сек** | Семьи, домохозяйства | Распределение ролей, потребление ресурсов, рождение детей | FamilySystem |
| **1 тик/мин** | Поселения, склады, мастерские | Производственные циклы, пополнение складов | ProductionSystem, MigrationSystem, FactionSystem |
| **1 тик/5 мин** | Регионы, торговля | Перерасчёт цен, движение караванов | TradeSystem |
| **1 тик/30 мин** | Государства, глобальная политика | Дипломатические акции, военные кампании | DiplomacySystem, WarSystem |
| **1 тик/ход (год)** | Исторические события, эпохи | Случайные события, климатические сдвиги | EventSystem, TechSystem, DegradationSystem, ChiefSystem |
| **1 тик/ход (сезон)** | Палеолит — сезонный цикл | Миграция стад, зима, весенние рождения | +SeasonalSystem (только в темпе «вождя» — D-015) |
| **1 тик/ход (1-5 лет)** | Античность+ — автопрокрутка рутины | Рутина между большими решениями | AutoTickSystem (только в темпе «эпохи» — D-015) |

### Связь частот тика с темпом игрока (D-015)

| Темп игрока (D-015) | Ход = | Какие частоты активны | Игрок |
|---|---|---|---|
| **Вождя** (палеолит-неолит) | 1 сезон | 1/сек, 1/10сек, 1/мин, 1/ход (сезон) | Активно решает каждые 30 сек |
| **Поколения** (бронза-железо) | 1 год | 1/сек (близкие), 1/10сек, 1/мин, 1/5мин, 1/30мин, 1/ход (год) | Решает о фракциях, реформах |
| **Эпохи** (античность+) | 1-5 лет | 1/сек (близкие), 1/мин, 1/5мин, 1/30мин, 1/ход (1-5 лет) + AutoTickSystem | Решает стратегически |

**Принцип**: при переключении темпа — частоты тика **не меняются**, меняется только **сколько ходов проходит между решениями игрока**. В темпе «эпохи» рутина автопрокручивается, игрок вмешивается по триггерам.

## 🎯 Бесшовный переход «личность → абстракция»

> 📋 **Из аудита Модели B (§4 SoS сравнение)**: «Кэп индивидуальности: имена/личности — первым ~200-500 гражданам, выше — агрегация по домохозяйствам/гильдиям»

### Принцип

> При населении > N в поселении — граждане агрегируются. До N — индивидуальности.

**N = 500** (по аудиту Модели B). Это значит:
- **Первые 500 граждан в поселении** — индивидуальности (имя, навыки, потребности, лояльность)
- **Граждане 501+** — агрегируются в «когорты» по домохозяйствам/гильдиям

### Реализация

#### Сценарий 1: Малое поселение (≤ 500 чел.)

Все граждане — индивидуальности. Каждая имеет полный набор компонентов (Identity, Skills, Needs и т.д.). CitizenActionSystem тикает 1/сек для ближайших 100, 1/10сек для остальных.

#### Сценарий 2: Большое поселение (> 500 чел.)

Первые 500 — индивидуальности (как сценарий 1). Граждане 501+ — агрегируются:

```csharp
public struct CohortEntity : IComponentData {
    public int cohortId;
    public int settlementId;
    public CohortType type;           // Household/Guild/AgeGroup
    public int memberCount;           // сколько в когорте
    public byte averageAge;
    public byte averageLoyalty;
    public int4 dominantSkills;       // топ-4 навыка
    public long aggregateWealth;
    public int factionId;             // -1 если нет
}

public enum CohortType : byte {
    Household,   // домохозяйство (семья)
    Guild,       // гильдия (по профессии)
    AgeGroup,    // возрастная группа
    Caste        // каста (поздние эпохи)
}
```

**CohortSystem** (1/мин) — обновляет агрегированные показатели когорт вместо отдельных граждан.

### Когда индивидуальность, когда когорта?

| Ситуация | Что |
|---|---|
| Игрок кликает на гражданина в ближней зоне | Индивидуальность (всегда, даже в большом поселении) |
| Гражданин входит в «ближние 100» к камере | Индивидуальность (даже если 501+) |
| Гражданин в дальнем поселении | Когорта (если 501+) |
| Игрок назначает чемпиона/наследника/командира | Индивидуальность (выбирается из когорты) |
| Смерть/рождение в дальней когорте | Обновляется memberCount, не создаётся новая индивидуальность |

### Порог переключения

- **N = 500** на поселение (по аудиту)
- При росте населения > 500 — лишние граждане агрегируются
- При убывании < 500 — когорты распадаются обратно в индивидуальности (по приоритету: чемпионы, ключевые профессии)

## 📊 Профиль нагрузки

### Расчёт ops/сек

**Сценарий**: 30 000 граждан, 500 поселений, 10 000 зданий, 50 AI-цивилизаций, 64 800 гексов.

| Система | Entity | Частота | Ops/сек |
|---|---|---|---|
| CitizenNeedSystem | 100 (ближние) | 1/сек | 100 |
| CitizenActionSystem | 100 (ближние) | 1/сек | 100 |
| CitizenMovementSystem | 100 (ближние) | 1/сек | 100 |
| FamilySystem | 5 000 (агрегированные семьи) | 1/10сек | 500 |
| ProductionSystem | 10 000 зданий | 1/мин | 167 |
| MigrationSystem | 100 (ближние, индивидуальные) + 500 когорт | 1/мин | 10 |
| FactionSystem | 50 (3-9 × ~10 государств) | 1/мин | 1 |
| TradeSystem | 50 караванов | 1/5мин | 0.2 |
| DiplomacySystem | 50 AI | 1/30мин | 0.03 |
| WarSystem | 10 армий | 1/30мин | 0.006 |
| EventSystem | (проверка триггеров) | 1/ход | 0.05 (1/год) |
| TechSystem | 1 (игрок) + 50 AI | 1/ход | 0.05 |
| DegradationSystem | 51 (государств) | 1/ход | 0.05 |
| ChiefSystem | 51 (вождей) | 1/ход | 0.05 |
| VisibilitySystem | 64 800 гексов | 1/сек | **проблема!** |

### Проблема: VisibilitySystem × 64 800 гексов × 1/сек = 64 800 ops/сек

**Решение**: VisibilitySystem тикает 1/сек только для гексов в радиусе наблюдения игрока. Остальные — по событию (разведгруппа вошла → обновить).

**Оптимизированный профиль**:

| Система | Entity | Частота | Ops/сек |
|---|---|---|---|
| VisibilitySystem (только наблюдаемые) | ~100 гексов | 1/сек | 100 |
| CohortSystem (для больших поселений) | 1 000 когорт | 1/мин | 17 |
| **ИТОГО** | | | **~1 200 ops/сек** |

> 1 200 ops/сек — **подъёмно для одного ядра**. С ECS-параллелизмом — легко.

### Параллелизм

ECS-системы можно запускать в нескольких потоках:
- CitizenActionSystem — parallel by citizen (no shared state)
- ProductionSystem — parallel by building
- TradeSystem — parallel by caravan

**Безопасные системы** (можно параллелить):
- Читают только свои компоненты, пишут только свои компоненты
- Не зависят от других систем того же тика

**Небезопасные системы** (последовательно):
- EventSystem (читает всё, пишет события)
- ChiefSystem (читает фракции, пишет вождя)
- DiplomacySystem (читает AI, пишет отношения)

## 🔄 Game Loop с учётом LOD

```
GAME LOOP (60 FPS):
  // Каждый кадр:
  1. READ INPUT (мгновенно)
  2. SIMULATE:
     // 1/сек системы (только близкие к камере)
     if (timeSinceLastTick >= 1.0):
       CitizenNeedSystem.Update(b_close_citizens)
       CitizenActionSystem.Update(b_close_citizens)
       CitizenMovementSystem.Update(b_close_citizens)
       VisibilitySystem.Update(observed_hexes)
     
     // 1/10сек системы
     if (timeSinceLastTick >= 10.0):
       FamilySystem.Update(all_families)
     
     // 1/мин системы
     if (timeSinceLastTick >= 60.0):
       ProductionSystem.Update(all_buildings)
       MigrationSystem.Update(all_migrating)
       FactionSystem.Update(all_factions)
       CohortSystem.Update(all_cohorts)  // для больших поселений
     
     // 1/5мин системы
     if (timeSinceLastTick >= 300.0):
       TradeSystem.Update(all_caravans)
     
     // 1/30мин системы
     if (timeSinceLastTick >= 1800.0):
       DiplomacySystem.Update(all_aicivs)
       WarSystem.Update(all_armies)
     
     // 1/ход системы — когда игрок завершает ход
     if (player_pressed_end_turn):
       EventSystem.Update(all_state)  // генерация событий
       // ПАУЗА для выбора игрока в событиях
       TechSystem.Update(all_civs)
       DegradationSystem.Update(all_civs)
       ChiefSystem.Update(all_chiefs)
       // обновить хронику
  3. RENDER (асинхронно)
  4. UPDATE UI (асинхронно)
```

### Пауза для выбора (D-016)

> EventSystem генерирует события, но **не применяет** их. Игроку показывается диалог (D-016), симуляция ждёт выбора. После выбора — применяется consequence, потом продолжают остальные системы.

Это значит:
- 1/сек системы продолжаются (граждане двигаются, голод растёт)
- 1/ход системы **пауза** до выбора игрока
- Если игрок долго думает (> 30 сек) — автопауза 1/сек систем тоже

## 🎮 Связь с темпом игрока (D-015)

### Темп «вождя» (палеолит-неолит, ход = 1 сезон)

```
Каждый ход (1 сезон = ~3 месяца):
  - 1/сек системы тикают ~90 раз (3 месяца × 30 дней × 1/сек)
  - 1/10сек системы тикают ~8 000 раз
  - 1/мин системы тикают ~1 300 раз
  - 1/ход системы тикают 1 раз
  
Игрок: решает каждые 30-60 секунд (глаголы D-015)
Длительность хода: 3-8 минут (D-015)
```

### Темп «поколения» (бронза-железо, ход = 1 год)

```
Каждый ход (1 год):
  - 1/сек системы тикают ~31 500 000 раз (365 дней × 24 × 3600) — НО это симуляция, не реально
  - На самом деле: движок «ускоряет» время, считает агрегированно
  
Реализация:
  - 1/сек системы тикают только ближайшие 100 граждан × N раз (N = сколько сезонов прошло)
  - Но это слишком много. Решение:
    - В темпе «поколения» 1/сек системы тикают 4 раза (по сезону)
    - 1/10сек системы тикают 12 раз (по месяцу)
    - 1/мин системы тикают 365 раз (по дню) — НО это для 100 ближних, не всех
    - 1/ход системы тикают 1 раз
  
Игрок: решает каждые 1-3 минуты
Длительность хода: 3-8 минут (D-015)
```

### Темп «эпохи» (античность+, ход = 1-5 лет)

```
Каждый ход (1-5 лет):
  - AutoTickSystem прокручивает рутину между большими решениями
  - 1/сек системы тикают только ближайшие 100 × N (N = сезонов за ход)
  - 1/ход системы тикают N раз (N = лет за ход)
  - EventSystem срабатывает по триггерам (война, мятеж, милстоун) — пауза для игрока
  
Игрок: решает стратегически (1-2 решения/ход)
Длительность хода: 3-8 минут (D-015)
```

### Реализация «ускорения времени»

В темпах «поколения» и «эпохи» движок не считает каждый день. Вместо этого:
- Берёт статистику (например, производство за год = production_rate × 365)
- Применяет изменения одним батчем
- Случайные события (болезнь, нападение) — проверяются вероятностью × N дней
