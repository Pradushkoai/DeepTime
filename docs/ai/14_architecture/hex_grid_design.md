# T-004: Гекс-сетка + генерация мира — Спецификация

> 📋 **Спецификация T-004** — гексагональная сетка 360×180 = 64 800 гексов. Генерация мира из реальных геоданных. Локальный зум с процедурной развёрткой.
>
> **Принцип**: реальная Земля → бинарник → грузится в рантайме за секунды. Процедурная детализация при зуме.

---

## 🎯 Обзор

GDD §4 определяет:
- Гекс-сетка 360×180 = 64 800 гексов
- Один гекс = 50-100 км реального мира
- Генерация из реальных геоданных (SRTM, OSM, SoilGrids, USGS и т.д.)
- Локальный зум: гекс 50×50 км → локальная карта 1×1 км (процедурно, с сидом из координат)

Эта спека описывает:
1. Структура гекс-сетки (coords, индексация, соседи)
2. Пайплайн генерации мира (offline)
3. Бинарный формат хранения
4. Локальный зум с процедурной развёрткой
5. Связь с туманом войны (D-013)

## 🗺️ Гекс-сетка

### Координатная система

Используется **axial coordinates** (q, r) — стандарт для гексагональных сеток.

```
q: 0..359 (360 столбцов)
r: 0..179 (180 строк)
Итого: 64 800 гексов
```

**Преобразование в lat/lon** (для проекции на реальную карту):
```
lat = 90 - (r + 0.5) × (180 / 180) = 90 - (r + 0.5)
lon = -180 + (q + 0.5) × (360 / 360) = -180 + (q + 0.5)

// Гекс (0, 0): lat = 89.5, lon = -179.5 (северо-запад)
// Гекс (359, 179): lat = -89.5, lon = 179.5 (юго-восток)
// Гекс (180, 90): lat = -0.5, lon = 0.5 (экватор, нулевой меридиан)
```

> ⚠️ Гекс 50-100 км — это **упрощение**. На экваторе гекс ~100 км, на полюсах ~30 км (из-за проекции). Для игры это допустимо — геймплей важнее точности.

### Соседство

У каждого гекса 6 соседей (axial directions):

```
// Направления (q, r):
NE: (+1, -1)
E:  (+1,  0)
SE: ( 0, +1)
SW: (-1, +1)
W:  (-1,  0)
NW: ( 0, -1)

// На полюсах и краях — wrap-around (Земля — сфера)
// q=0 и q=359 — соседи (longitude wrap)
// r=0 и r=179 — НЕ соседи (полюса — особый случай)
```

### Индексация

```
hexId = r × 360 + q
// hexId 0..64799
// hexId = 0: гекс (0, 0) — северо-запад
// hexId = 64799: гекс (359, 179) — юго-восток
```

### Расстояние между гексами

```
function hexDistance(a, b):
    return (abs(a.q - b.q) + abs(a.q + a.r - b.q - b.r) + abs(a.r - b.r)) / 2
```

## 🌍 Пайплайн генерации мира (offline)

> Запускается **один раз** при сборке игры. Результат — бинарный файл ~200-500 МБ.

### Источники данных (GDD §4)

| Источник | Что | Разрешение | Размер |
|---|---|---|---|
| NASA SRTM | Рельеф (высоты) | 30 м | ~30 ГБ растров |
| ASTER GDEM | Рельеф (полярные регионы) | 30 м | ~10 ГБ |
| OpenStreetMap | Реки, озёра, леса | вектор | ~50 ГБ |
| GEBCO | Батиметрия океана | 450 м | ~5 ГБ |
| Koppen-Geiger | Климатические зоны | вектор | ~100 МБ |
| MODIS (NASA) | Спутниковая растительность | 250 м | ~10 ГБ |
| SoilGrids (ISRIC) | Почвы | 250 м | ~5 ГБ |
| USGS MRDS | Месторождения полезных ископаемых | вектор | ~500 МБ |
| BGS | Европейская геология | вектор | ~100 МБ |
| ВСЕГЕИ | Российская геология | вектор | ~100 МБ |

### Этапы генерации

#### Этап 1: Импорт растров

```python
# Python скрипт (offline)
import rasterio
import geopandas

# SRTM — высоты
srtm = rasterio.open('srtm_global.tif')
heights = srtm.read(1)  # массив 36000×18000 (30 м разрешение)

# SoilGrids — почвы
soils = rasterio.open('soilgrids.tif')
soil_data = soils.read(1)

# MODIS — растительность
modis = rasterio.open('modis_landcover.tif')
landcover = modis.read(1)
```

#### Этап 2: Агрегация в гексы

Для каждого из 64 800 гексов:
1. Вычислить bounding box по (q, r)
2. Вырезать кусок из растров
3. Агрегировать:
   - Elevation: median (для устойчивости к выбросам)
   - TerrainType: mode (наиболее частый)
   - Fertility: average
   - Climate: from Koppen-Geiger polygon
   - WaterAccess: distance to nearest OSM water body
   - Resources: from USGS point data (within hex)
   - Fauna/Flora: from biome lookup table

#### Этап 3: Постобработка

- Сглаживание границ (гекс не должен быть «полосатым»)
- Проверка связности (реки текут вниз, не вверх)
- Заполнение пропусков (без данных → biome default)

#### Этап 4: Сериализация

```python
# Бинарный формат (custom, для быстрой загрузки)
import struct

with open('world.bin', 'wb') as f:
    # Header
    f.write(struct.pack('III', 360, 180, 64800))  # q_count, r_count, hex_count
    
    # Hex data (64 800 × ~80 байт = ~5 МБ... но с ресурсами ~200 МБ)
    for hex_id in range(64800):
        hex_data = encode_hex(hex_id)
        f.write(hex_data)
```

### Бинарный формат hex

```
// ~80 байт на гекс (без ресурсов) → ~5 МБ
// ~300 байт с ресурсами → ~20 МБ
// + Flora/Fauna ссылки → ~50 МБ
// ИТОГО: ~50-200 МБ бинарник

struct HexData {
    int16 elevation;          // 2 байта (метры)
    uint8 terrainType;        // 1 байт
    uint8 biome;              // 1 байт
    uint8 climateZone;        // 1 байт (Koppen-Geiger)
    uint8 fertility;          // 1 байт (0-100)
    uint8 waterAccess;        // 1 байт (0-100)
    int16 resources[7];       // 14 байт (7 ресурсов: 3 surface + 2 subsurface + 1 deep + 1 reserved)
    int32 firstFaunaId;       // 4 байта (linked list в отдельный файл)
    int16 faunaCount;         // 2 байта
    int32 firstFloraId;       // 4 байта
    int16 floraCount;         // 2 байта
    int8 soilId;              // 1 байт (32 WRB)
    uint8 reserved;           // 1 байт (выравнивание)
    float lat, lon;           // 8 байт
}  // ~50 байт
```

### Загрузка в рантайме

```csharp
// Unity C#

}
```

## 🔍 Локальный зум с процедурной развёрткой

> GDD §4: «Когда игрок зумит в конкретный гекс, генеративная система разворачивает этот гекс (50×50 км) в локальную карту 1×1 км (или 2×2) с соответствующим рельефом, реками в нужных местах, лесом нужного типа, выходами песчаника и кремня на поверхности, дичью соответствующих видов, дикими злаками в подходящих местах»

### Принцип

> Процедурная генерация с сидом, полученным из координат гекса: если игрок вернётся в этот же гекс, карта будет та же.

### Сид гекса

```
function hexLocalSeed(hexId):
    return hash(hexId)  // детерминированный
    // одинаковый для одного и того же гекса всегда
```

### Локальная карта

- Размер: 50×50 (или 100×100) локальных ячеек = 50×50 км / 100 = 500 м каждая
- ИЛИ 1×1 км разрешение: 50×50 = 2500 ячеек по 1×1 км — слишком детально
- Компромисс: 25×25 = 625 ячеек по 2×2 км — достаточно для геймплея

### Что генерируется

| Элемент | Источник | Алгоритм |
|---|---|---|
| Рельеф | Elevation гекса + noise | Value noise с сидом |
| Реки | WaterAccess + flow simulation | Простой A* от истока к устью |
| Лес | Biome + density | Poisson disk sampling |
| Выходы камня | Resources.surface | Point process |
| Дичь | Fauna | По биому + density |
| Злаки | Flora (дикие) | По биому + fertility |
| Климат | ClimateZone | Static |

### Детерминизм

- Одинаковый сид → одинаковая карта
- Изменения игрока (вырубка, постройки) — отдельный слой, не влияет на процедурную базу
- При возврате в гекс — база та же, изменения игрока применяются поверх

### Когда генерировать

- **Лениво**: при первом зуме в гекс
- **Кэшировать**: локальная карта хранится в памяти, пока игрок рядом
- **Выгружать**: при уходе игрока > 5 гексов — выгрузить локальную карту (изменения игрока сохраняются)

## 🌫️ Связь с туманом войны (D-013)

> D-013: 4 состояния гекса (Unknown/Observed/InMemory/Known). HexVisibility — динамический компонент.

### Видимость на глобальной карте

| Состояние | Что видит игрок |
|---|---|
| **Unknown** | Чёрный/тёмный гекс, без деталей |
| **Observed** | Полная детализация (террейн, ресурсы, поселения, армии) |
| **InMemory** | Последнее увиденное состояние, устаревает (staleFlags) |
| **Known** | География (террайн, реки), но не текущее состояние |

### Радиус наблюдения (GDD §4 + D-013)

| Источник | Радиус |
|---|---|
| Стоянка (Camp) | 1 гекс |
| Поселение (Village) | 1-2 гекса |
| Город (Town/City) | 2-3 гекса |
| Разведчик пеший | 1-2 гекса |
| Разведчик конный | 2-3 гекса |
| Корабль | 2-4 гекса |
| Сторожевой пост | +1 к радиусу поселения |

### Обновление видимости

- **Observed** — гексы в радиусе наблюдения (обновляются 1/сек)
- **InMemory** — гексы, которые были Observed, но вышли из радиуса (устаревают: staleFlags показывает, что именно устарело — постройки, войска)
- **Known** — гексы, которые никогда не исследовались близко, но игрок знает географию (например, из торговых карт)
- **Unknown** — гексы, о которых игрок не знает ничего
