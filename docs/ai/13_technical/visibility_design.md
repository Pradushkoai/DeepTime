## 🎯 Обзор

Единый UI-слой индикаторов, показывающий игроку состояние общества. **Главный принцип**: «игрок не может нести ответственность за то, чего не видит». Любая штрафующая механика обязана иметь **предшествующий индикатор**.

**Инверсия главного экрана** (контрпредложение B, round_09): не статический дашборд из 7 категорий, а **только активные шкалы давления**. Пусто = тишина = хорошо. Игрок видит 2-3 растущих накопителя, а не 20 чисел.

## 📝 Подпись причины

> ⚠️ **B в round_09**: «Цвет отвечает "плохо", но не отвечает "почему" и "что делать". Каждая шкала давления обязана нести подпись причины».

### Принцип

> Каждый активный индикатор **обязан** показывать **причину** — не просто «обида 45», а «обида жречества: 40 лет не выделяли землю храму».

### Структура подписи

```
[Иконка] [Субъект]: [Параметр] [Значение]
         «[Причина — что произошло]»
         → [Рекомендация — что делать]
```

### Примеры подписей

| Индикатор | Подпись |
|---|---|
| 😡 Жречество: обида 45 | «40 лет не выделяли землю храму» → [Реформа: расширить храмовые земли] |
| ⚠️ Вождь: давление 60 | «Открыто 3 технологии, реформа не проведена» → [Провести реформу] |
| 📉 Безработица 25% | «Закрыто 3 мастерские после войны» → [Общественные работы] |
| ⛓️ Рабы 30% | «Высокая доля рабов» → [Манумиссия или риск бунта] |
| 🚨 Перенасыщение 0.7 | «Быстрый рост территории» → [Строить институты] |
| 🌍 Хетты: отношение −60 | «Убили торговца 50 лет назад» → [Требование возмещения или мир] |

### Цвет = второй канал, не единственный

| Цвет | Значение | Когда |
|---|---|---|
| 🟢 Зелёный | Норма | Не показывается (пусто) |
| 🟡 Жёлтый | Внимание | Давление >20 |
| 🔴 Красный | Критично | Давление >80 |

> Цвет **дополняет** подпись, не заменяет. Дальтоники видят подпись.

## 🔔 Алерты

> ⚠️ **B в round_09**: «Алерты — ошибка, а не частота. Алерт срабатывает на смену состояния (норма → внимание), не на каждый рост; инерция — показав один раз, не повторять, пока состояние не изменилось».
>
> ⚠️ **A в round_10**: добавил «отключаемые для опытных».

### 2 правила алертов

| Правило | Что | Зачем |
|---|---|---|
| **Смена состояния** | Алерт при переходе норма → внимание → критично | Не на каждый рост значения |
| **Инерция** | Показав один раз, не повторять, пока состояние не изменилось | Закрывает popup-ад |

### Типы алертов

| Тип | Когда | Пример |
|---|---|---|
| ℹ️ Информационный | Событие (не угроза) | «Появилась фракция: Земледельцы» |
| ⚠️ Предупреждение | Смена состояния норма → внимание | «Обида жречества растёт: 25» |
| 🚨 Критический | Смена состояния внимание → критично | «МЕТЕЖ: жречество подняло восстание!» |

### Отключаемые

| Опция | Что | Для кого |
|---|---|---|
| «Только критические» | Скрывает ℹ️ и ⚠️ | Опытные игроки |
| «Все алерты» (по умолчанию) | Показывает все | Новички |
| «Только подписи» | Скрывает алерты, но показывает подписи на главном экране | Эксперты |

## 📋 4 принципа слоя видимости

| # | Принцип | Что значит |
|---|---|---|
| 1 | **Штрафующая механика обязана иметь предшествующий индикатор** | Нельзя наказывать за то, чего игрок не видел |
| 2 | **Давление опережает срабатывание** | Игрок видит накопление до того, как оно выстрелит |
| 3 | **Раздельное отображение связанных шкал** | Сила и обида фракций НЕ склеиваются в одну |
| 4 | **Связь с паттерном «накопление → срабатывание»** | Все накопители (обида, давление, перенасыщение) отображаются единым образом |

### Принцип 1: предшествующий индикатор

> Если механика наказывает игрока (−счастье, мятеж, кризис), игрок **обязан** видеть накопление **до** наказания.

| Механика | Индикатор | Наказание |
|---|---|---|
| Обида фракции → мятеж | 😡 Обида >80 (видна заранее) | Мятеж в кризис |
| Давление вождя → смерть | ⚠️ Давление >50 (видна заранее) | Кризис преемственности |
| Безработица → недовольство | 📉 Безработица >15% (видна) | −счастье, риск мятежа |
| Перенасыщение → распад | 🚨 Перенасыщение >0.6 (видно) | Гражданская война |

### Принцип 3: раздельные шкалы

> ⚠️ **Условие из Q-003 дискуссии**: сила и обида фракций **не должны склеиваться** в одну.

```
❌ НЕПРАВИЛЬНО:
   Жречество: ████░░ 65  (что это — сила или обида?)

✅ ПРАВИЛЬНО:
   Жречество:
     Сила:  ████░░ 65  (способность действовать)
     Обида: ██░░░░ 30  (готовность против тебя)
```

## 🔍 Explainability — причина в одну строку (R7, v0.29)

> 📋 **Из аудита Модели B (R7, И-4)**: D-007 подписывает причины только алертов давлений, но не причин решений граждан. В RimWorld инспектор гражданина показывает причину каждого решения — это стандарт жанра симуляции агентов. У нас подпись причины уже есть (см. выше) — распространить с алертов на решения.

### Принцип

> Каждое решение гражданина, каждый поток миграции, каждое AI-размещение здания **обязано** показывать **причину** — не просто «кузнец Анна уехала», а «Анна уехала: в городе 0 вакансий кузнецов, в посёлке 3, цена переезда 50».

### 3 расширения подписи причины

#### 1. Инспектор гражданина (решения)

> Гражданин выбирает действие по utility score (GDD §7). Формулы есть, объяснения нет: игрок не узнает, почему кузнец Анна осталась, а кузнец Борис уехал.

**Стандарт RimWorld**: инспектор показывает причину каждого решения.

**Реализация**:
```
[Гражданин: Анна, кузнец]
Текущее действие: «Охочусь»
Причина: «голод 70, навык охоты 80, приоритет племени = запасы»
Альтернатива (не выбрана): «Кузнечное дело» —Utility ниже (нет заказа)
```

| Поле | Что показывает |
|---|---|
| Текущее действие | Что делает сейчас |
| Причина | Почему это действие (параметры utility score) |
| Альтернатива | Что не выбрал и почему (более низкий utility) |

#### 2. Потоки миграции

> Мигрант выбирает место по нужды×ценности×вакансия×эдикты (D-003). Игрок не видит, почему дом вырос здесь, а не там.

**Реализация**: при клике на дорогу/поток миграции:
```
[Поток: из Города в Посёлок]
Направление: 5 семей / год
Причина: «вакансии кузнецов: Город 0, Посёлок 3»
Доп. факторы: «ценности племени = коллективизм (Посёлок ближе), нет эдикта ограничения»
```

#### 3. AI-размещение зданий (D-002 heatmap)

> Здания ставит AI по якорям (D-002). Игрок не понимает, почему дом вырос здесь.

**Реализация**: при наведении на новое здание:
```
[Дом семьи Бориса]
Почему здесь: «у воды (+30), у дороги (+20), не у пожара (+10)»
Альтернативы (не выбраны): «у реки (+35), но дальше от дороги (−15)»
```

Heatmap кластеризации уже есть в D-002 — добавить подпись причины каждого решения.

### Прецедент

- **RimWorld** — инспектор гражданина с причинами каждого решения (стандарт жанра симуляции агентов)
- **Dwarf Fortress** — мысли дварфов с подробными причинами

### Что лечит

- **И-4 (Невидимая причинность агентов)** — игрок понимает, почему кузнец Анна осталась, а кузнец Борис уехал
- Симуляция перестаёт быть чёрным ящиком фрустрации

## 🎉 Позитивный канал — Хроника дня (R6, v0.29)

> 📋 **Из аудита Модели B (R6, И-5)**: D-007 — экран проблем: показываются только растущие давления, «пусто = хорошо». Достижения спрятаны в хронике (D-001), но хроника — текстовый лог, не канал дофамина. Игрок 90% времени видит «что плохо» и 10% — «что случилось». Нет «первого горшка обожжён», «первого зерна выращенного».

### Принцип

> Рядом с экраном проблем — лента событий-наград. Каждое «впервые» — праздничное событие с выбором. Игрок видит не только «что плохо», но и «что хорошо».

### Структура

```
[Экран проблем (D-007 инверсия)]    [Хроника дня (R6)]
- 😡 Жречество: обида 45           🎉 Первый горшок обожжён!
- ⚠️ Вождь: давление 60            🎉 Родился первый ребёнок нового рода
- 📉 Безработица 25%               🎉 Караван вернулся с обсидианом
                                   🎉 Кузнец Карл стал лучшим мастером долины
```

### Типы позитивных событий

| Тип | Пример | Триггер |
|---|---|---|
| **Первое достижение** | «Первый горшок обожжён», «Первое зерно выращено», «Дочь вождя вышли за соседа» | Срабатывает один раз при первом выполнении |
| **Мастерство** | «Кузнец Карл стал лучшим мастером долины» | Гражданин достигает навыка 90+ |
| **Возврат** | «Караван вернулся с обсидианом» | Успешная торговая экспедиция |
| **Семья** | «Родился первый ребёнок нового рода» | Заметное рождение |
| **Культура** | «Первый храм завершён», «Летописец записал первый год» | События культуры |

### Связь с D-016 События

Подробный формат позитивных событий — в D-016 Система событий (секция «Позитивный канал — Хроника дня»). Целевая частота: 1 позитивное событие / 10-15 минут (между кризисами).

### Что лечит

- **И-5 (Нет позитивного канала награды)** — игрок видит не только проблемы, но и достижения
- Для длинной игры (десятки часов на цивилизацию) — отсутствие позитивного пульса = риск выгорания на тихих отрезках
- Дофаминовая петля «сделал → увидел результат → захотел ещё»
