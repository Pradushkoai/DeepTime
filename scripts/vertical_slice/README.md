# Vertical Slice Prototype (Python, headless)

> 📋 **Python-прототип симуляции** для проверки ядра DeepTime без UI. Реализует T-008 (Vertical Slice) в headless-режиме.

## 🎯 Цель

Проверить ядро симуляции (D-001 вождь, D-004 фракции, D-015 контракт сессии, D-016 события) без рендера. Ответить на вопрос: «работает ли ядро архитектурно?»

**Это НЕ плейтест** — нет UI, игрок не взаимодействует. Это **доказательство концепции**: ECS, системы, EventSystem, game loop — всё работает вместе.

## 🚀 Запуск

```bash
cd /home/z/my-project/DeepTime
python3 scripts/vertical_slice/vertical_slice_prototype.py
```

Вывод: состояние каждые 10 ходов + итоговый отчёт с метриками.

## 📊 Что реализовано

### Архитектура (по T-001..T-008)

| Спека | Что реализовано |
|---|---|
| **T-001 Архитектура** | 4 слоя (упрощённо: Data/Simulation, без Render/UI), game loop, детерминизм от seed |
| **T-002 Структура данных** | ECS на dataclasses: Citizen, Family, Faction, Chief, Event, Settlement |
| **T-003 LOD-симуляция** | Упрощённо: 1/ход (все системы тикают раз в ход) |
| **T-005 EventSystem** | 11 типов событий, очередь с приоритетами (CRITICAL/HIGH/NORMAL/LOW), EventResolver |
| **T-008 Vertical Slice** | 1 поселение, 50 граждан, 5 ресурсов, 3 фракции, 100 ходов (25 лет) |

### Дизайн-спеки (D-001..D-017)

| Спека | Что реализовано |
|---|---|
| **D-001 Вождь** | Давление (0-100), эра (YOUNG/MATURE/OLD/DECLINING), смерть от давления/возраста, наследование |
| **D-003 Миграция** | Utility score для выбора действия (охота/собирательство/рыболовство/строительство/отдых/ритуал) |

| **D-007 Видимость** | R7 explainability — `action_reason` и `action_alternative` у каждого гражданина |
| **D-009 Альт. пути** | Архетипы (FOREST/STEPPE/...) с долями калорий |
| **D-013 Туман войны** | Не реализован (1 поселение, не нужен для среза) |
| **D-015 Контракт сессии** | Темп «вождя» (1 ход = 1 сезон), онбординг «зима идёт» (старт с SUMMER) |
| **D-016 События** | 11 типов: CHIEF_DEATH, WINTER_COMING, HUNGER, FACTION_GRIEVANCE, CHAMPION_PROPOSES, RITUAL_OF_YEAR, WEDDING, BIRTH_NOTABLE, DEATH_ELDER, GOOD_HARVEST, FIRST_POT |
| **R3 Перекалибровка** | Не реализован (нет технологий в срезе) |

| **R7 Explainability** | `action_reason` у каждого гражданина |
| **R9 Предохранители** | CHIEF_SUCCESSION с выбором «Долг отцов» / «Новая метла» |

### Системы

| Система | Частота | Что делает |
|---|---|---|
| `system_citizen_needs` | 1/ход | Голод растёт, усталость от работы |
| `system_citizen_actions` | 1/ход | Выбор действия по utility score (R7 explainability) |
| `system_production` | 1/ход | Производство еды/дерева (с сезонным множителем) |
| `system_consumption` | 1/ход | Потребление еды, голод, смерть от голода |
| `system_factions` | 1/ход | Сила = доля населения, обида растёт от давления вождя |
| `system_chief` | 1/ход | Давление от голода/зимы/смертей/обиды, эра, смерть |
| `system_aging_and_death` | 1/год | Старение, естественная смерть (старики) |
| `system_random_crises` | 1/ход | Жёсткая зима (15%), неурожай (10%), болезнь (3%), хищник (2%) |
| `system_events_check` | 1/ход | Триггеры событий |

### Стратегии AI (для auto-симуляции)

|---|---|
| `auto` | Всегда первый выбор |

- **Вождь Ивар** правил 22 года, давление 100, умер в ходе 98 (выбрана «Новая метла»)
- **Жёсткие зимы** 2 раза — потери еды
- **Неурожаи ягод** 2 раза
- **Болезни** унесли стариков и детей
- **Хищники** атаковали охотников
- **Все 3 фракции** дошли до обиды 100 — мятеж
- **3 реформы** проведено (чемпионы предлагали)

## 🔧 Итеративные правки (5 циклов)

Подробно в `worklog.md` (Task ID: VS-PYTHON-1). Кратко:

1. **Прогон 1**: 50→1 (вымерли). Производство мяса = 0 из-за `int()` округления.
2. **Прогон 2**: 50→9. Поднял производство, но все шли BUILD (housing deficit бонус = 30).
3. **Прогон 3**: 50→104. Переписал utility score (food_crisis флаг, строительство блокируется в кризис). Слишком легко — давление = 0.
4. **Прогон 4**: 50→81, давление 100. Добавил кризисы (жёсткая зима, неурожай, болезнь, хищник) + усилил давление вождя.

**Главный урок**: малые изменения в формулах utility score → большие изменения в поведении. Подтверждает важность R7 (explainability) — без понимания «почему гражданин выбрал это действие» балансировка невозможна.
