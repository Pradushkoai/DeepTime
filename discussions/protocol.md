# 📋 Protocol — Как дискутировать

> **Этот файл — правила ведения дискуссии.** Обе модели обязаны их соблюдать.

---

## 🔄 Раунд дискуссии

Один раунд = один цикл «вопрос → ответ → реакция». Раунд считается завершённым, когда обе модели высказались.

### Структура раунда:

```
1. Модель A (инициатор) → публикует вопросы + начальную позицию
2. Модель B → читает, формирует свою позицию, отвечает с маркерами
3. Модель A → читает ответ B, реагирует (✅/❌/⚠️)
4. (если не консенсус) Модель B → реагирует на реакцию A
5. Повторяем до консенсуса или deadlock (3 раунда)
```

---

## 📝 Формат файла раунда

Имя файла: `rounds/round_XX_YYYY-MM-DD.md` (XX — номер, дата создания)

### Шаблон:

```markdown
# 🔄 Раунд XX — YYYY-MM-DD

**Участники**: Модель A (GLM), Модель B (???)
**Статус раунда**: 🟡 ACTIVE / ✅ CLOSED / ❌ DEADLOCK

---

## 📌 Вопрос 01: [Название]

### Позиция Модели A (предыдущий раунд / начальная):
[Кратко: что предлагала A]

### Ответ Модели B:
**Маркеры**: ✅ / ❌ / ⚠️

[Аргумент B]

### Реакция Модели A:
**Маркеры**: ✅ / ❌ / ⚠️

[Контраргумент или согласие]

### Итог по вопросу 01:
- ✅ CONSENSUS — оба согласны с [решение]
- 🟡 DISCUSSING — нужно ещё раундов
- ❌ DEADLOCK — передаём пользователю

---

## 📌 Вопрос 02: [Название]
...
```

---

## 🏷 Маркеры согласия — обязательное использование

| Маркер | Значение | Когда ставить |
|---|---|---|
| ✅ | Полностью согласен | Аргумент партнёра принял без замечаний |
| ⚠️ | Частично согласен / компромисс | Принял с условием/модификацией |
| ❌ | Не согласен | Аргументирую почему |
| 🔄 | Нужно обсудить подробнее | Не хватает данных для решения |
| 🆕 | Новая идея | Предложил то, чего не было в изначальном вопросе |

**Правило**: каждое ❌ должно сопровождаться аргументом (почему не согласен) и контрпредложением.

---

## 📊 Статусы вопросов

В каждом файле `questions/NN_topic.md` есть заголовок со статусом:

```yaml
---
статус: OPEN / DISCUSSING / CONSENSUS / DEADLOCK / USER_DECIDED
приоритет: высокий / средний / низкий
последний_раунд: round_XX
согласие_модели_A: none / partial / full
согласие_модели_B: none / partial / full
---
```

**Обновляй эти поля после каждого раунда.**

---

## 🛑 Когда переходить к пользователю (DEADLOCK)

Условия для статуса `DEADLOCK`:
1. **3 раунда** без прогресса (модели повторяют аргументы)
2. Принципиальное расхождение в ценностях (например, «сложность vs простота»)
3. Обе модели предлагают взаимоисключающие решения
4. **Общее число раундов достигло потолка** (по умолчанию 7) — даже если есть прогресс, но раунды кончились → пользователь решает (дополнение из раунда 06)

> ⚠️ **Уточнение (раунд 06)**: правило «общего числа раундов» — это **дополнение** к правилу «3 раунда без прогресса», не замена. Ситуация «есть прогресс, но раунды кончились» не должна быть формальным deadlock'ом — это отдельный случай, требующий решения пользователя.

При `DEADLOCK`:
1. Модель, которая обнаружила deadlock, ставит статус `DEADLOCK` в файле вопроса
2. Создаёт файл `rounds/deadlock_NN_topic.md` с описанием позиций обеих сторон
3. Пишет в чат пользователю: «По вопросу NN deadlock — нужно твоё решение»

---

## 🔄 Правило отката ❌ (дополнение из раунда 06)

Откат своего ❌ возможен, но не по счётчику «один раз за вопрос». Вместо счётчика:

**Условие**: откат допустим, если новая аргументация **апеллирует к другому принципу или новому факту**, а не является переформулировкой прежней.

**Проверяет**: партнёр (как и любую аргументацию).

**Пример**: в вопросе 02 Модель B откатила свой ❌ по налогу на безработицу, апеллируя к Принципу 9 (бесконечное развитие, не закрывать пути). Это прошла бы и со вторым разом, если бы появился новый принцип.

---

## ✅ Когда вопрос закрыт (CONSENSUS)

Условия для статуса `CONSENSUS`:
1. Обе модели поставили ✅ по всем подпунктам
2. Нет открытых ❌ или ⚠️

При `CONSENSUS`:
1. Модель, которая видит согласие, ставит статус `CONSENSUS`
2. Записывает решение в `consensus.md`
3. Помечает в `questions/NN_topic.md` итог: «Перенесено в consensus.md»

---

## 📐 Правила аргументации

### ✅ Хорошо:
- «Предлагаю механизм X, потому что: 1) решает проблему Y, 2) исторически достоверно, 3) не блокирует другие механики»
- «Не согласен с твоим вариантом, потому что: violates Принцип 9 (нет альтернативы). Контрпредложение: Z»
- «Частично согласен — принимаю основу, но предлагаю упростить пункт 3»

### ❌ Плохо:
- «Это плохо» (без аргумента)
- «Лучше сделать круто» (без конкретики)
- «Согласен» (без ✅ маркера и без указания, с чем именно)

---

## 🚫 Что нельзя делать

1. **Молча соглашаться** — всегда ✅/❌/⚠️ + аргумент
2. **Игнорировать вопросы** — отвечать на все, даже если «не знаю»
3. **Уходить в детали** (Принцип 2) — концептуальный уровень
4. **Блокировать без альтернативы** (Принцип 9) — всегда предлагай параллельный путь
5. **Решать за пользователя** (Принцип 7) — только предложить, финал за ним
6. **Менять чужой текст** — только добавлять свои реакции в свой раздел

---

## 🔄 Порядок хода

В каждом раунде:
1. Сначала отвечает **Модель B** (приглашённая) на начальные позиции
2. Потом **Модель A** реагирует на ответы B
3. Потом **Модель B** реагирует на реакцию A
4. И т.д.

**В следующем раунде — наоборот**: A начинает с новых вопросов, B отвечает.

Это обеспечивает симметрию — обе модели бывают и в роли инициатора, и в роли критика.

---

## 📦 Что делать в конце дискуссии

1. Все вопросы со статусом `CONSENSUS` → переносим в `consensus.md` с описанием решения
2. Все вопросы со статусом `DEADLOCK` → пользователь решает → статус `USER_DECIDED`
3. Пользователь утверждает `consensus.md` → переносим в `decision_log.md` проекта
4. Реализуем решения (если нужно — в коде/документации)

---

## 💡 Советы для качественной дискуссии

1. **Читай внимательно** — не отвечай на то, что не говорили
2. **Цитируй** — приводи конкретные фразы партнёра при ❌
3. **Будь конкретен** — предлагай механику, а не «идею»
4. **Уважай Принцип 9** — всегда ищи параллельные пути
5. **Думай о игроке** — как это будет ощущаться в игре?
6. **Помни о стадии** — мы на концептуальной, не формализуй до формул
