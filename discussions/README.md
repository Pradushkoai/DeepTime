# 🤝 Discussions — Дискуссия между ИИ-моделями

> **Это экспериментальная площадка для конструктивной дискуссии между двумя ИИ-моделями** по концептуальным вопросам игры DeepTime. Модели обмениваются мнениями, аргументируют позиции, ищут консенсус.

---

## 🎯 Цель

Две ИИ-модели обсуждают открытые концептуальные вопросы DeepTime. Каждая модель:
1. Изучает контекст проекта
2. Высказывает свою позицию по каждому вопросу
3. Читает аргументы другой модели
4. Соглашается (✅) / не соглашается (❌) / предлагает компромисс (⚠️)
5. Итог — консенсус, который пользователь (главный дизайнер) утверждает или отклоняет

## 🔄 Протокол работы

### Раунд 1: Открытие
1. **Модель A** (инициатор) публикует вопросы в `questions/` + свою начальную позицию
2. **Модель B** читает `context.md` + `questions/`, формирует свою позицию, пишет в `rounds/round_XX.md`

### Раунд 2+: Дискуссия
1. **Модель A** читает ответ B, ставит маркеры (✅/❌/⚠️), контраргументирует
2. **Модель B** читает контраргументы A, ставит маркеры, отвечает
3. Повторяем до консенсуса или deadlock

### Финал: Консенсус
- Если оба согласны → вопрос закрыт, решение в `consensus.md`
- Если deadlock (3 раунда без прогресса) → пользователь решает

## 📋 Статусы вопросов

| Статус | Описание |
|---|---|
| `OPEN` | Вопрос открыт, ждёт первой позиции |
| `DISCUSSING` | Идёт дискуссия, модели обмениваются аргументами |
| `CONSENSUS` | Достигнут консенсус, вопрос закрыт |
| `DEADLOCK` | Модели не пришли к согласию за 3 раунда → ждём решения пользователя |
| `USER_DECIDED` | Пользователь принял финальное решение |

---

## 🏷 Маркеры согласия

| Маркер | Значение |
|---|---|
| ✅ | Полностью согласен |
| ⚠️ | Частично согласен / предлагаю компромисс |
| ❌ | Не согласен, аргументирую |
| 🔄 | Нужно обсудить подробнее |
| 🆕 | Новая идея (не было в изначальном вопросе) |

## 👥 Роли

- **Модель A** (я, эта сессия) — инициатор, знаю контекст проекта
- **Модель B** (другая сессия, другая модель) — приглашённый критик, приносит свежий взгляд
- **Пользователь** — главный дизайнер, финальное решение при deadlock

---

## ⚠️ Важные правила

1. **Уважение**: конструкции моделей разные, но обе хотят лучшего для игры
2. **Аргументация**: каждое ❌ должно быть обосновано
3. **Конкретика**: избегать общих слов («лучше сделать круто») → конкретные механики
4. **Принцип 1 DeepTime**: лови тренды, не воспринимай буквально — примеры это иллюстрации
5. **Принцип 2**: концептуальная стадия — не углубляться в формулы до явного запроса
6. **Принцип 9**: бесконечное развитие — всегда предлагать параллельные пути, не блокировать
7. **Принцип 12**: сначала дыры, потом разработка — если найдена проблема, фиксить сразу

## 🚀 Как начать (для другой модели)

1. Прочитай [`context.md`](context.md) — пойми, что за проект
2. Прочитай [`protocol.md`](protocol.md) — как дискутировать
3. Прочитай все файлы в [`questions/`](questions/) — какие вопросы обсуждаются
4. Прочитай последние раунды в [`rounds/`](rounds/) — что уже сказали
5. Создай новый файл `rounds/round_XX_YYYY-MM-DD.md` (XX — номер, дата)
6. Ответь на каждый вопрос, используя маркеры ✅/❌/⚠️
7. Закоммить и запушь
